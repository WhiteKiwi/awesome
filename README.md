## 아티클

### [기술 부채, 인지 부채, 의도 부채… '부채'라는 말을 너무 쉽게 쓰고 있다](https://codex.epril.com/misuse-of-debt-metaphor-in-software-development)

기술 부채의 원래 은유를 되짚으며, 원금·이자·상환이라는 개념으로 기술 부채와 다른 종류의 문제를 구분하는 글.

<sub>`기술 부채` · `소프트웨어 설계` · `AI 코딩` · 2026-10-19</sub>

> **남긴 생각** — 부채를 정의하고, 원금은 더 나은 이해를 아직 반영하지 못한 코드, 이자는 점점 커지는 변경 비용에 대응시킨 비유가 인상적.

### [How to Write Usefully](https://www.paulgraham.com/useful.html)

독자에게 새롭고 중요한 사실을 정확하고 분명하게 전달하려면 무엇이 필요한지, 초고를 고치며 생각을 다듬는 과정을 설명하는 에세이.

<sub>`글쓰기` · `에세이` · 2026-10-16</sub>

### [Genies Grant Wishes Only to Teach You a Lesson](https://vladikk.com/2026/05/01/ai-genies/)

LLM을 소원을 들어주는 지니에 빗대어, AI 코딩에도 명확한 목표와 도메인 이해, 모듈식 설계가 필요하다고 이야기하는 글.

<sub>`AI 코딩` · `DDD` · `모듈식 설계` · 2026-10-16</sub>

### [Why Go is an Ideal Language for AI-Assisted Software Engineering](https://developers.googleblog.com/why-go-is-an-ideal-language-for-ai-assisted-software-engineering/)

빠른 컴파일과 일관된 코드, 통합 도구가 AI 생성 코드를 검토하고 검증하는 반복에 유리하다는 관점.

<sub>`Go` · `AI 코딩` · `개발 생산성` · 2026-10-13</sub>

> **남긴 생각** — 여러 언어를 시도하며 AI가 쓰기 좋은 언어가 무엇인지, 언어보다 구조와 기반이 더 중요한지 고민 중. 큰 Rust 프로젝트에서 변경 패키지만 빌드·테스트하고 CI/CD 최적화 레퍼런스를 찾아 적용해도 대기 시간이 길어 반복 횟수의 병목으로 느꼈고, 다른 언어를 찾다가 읽은 글.

### [서버 모니터링 분석 가이드](https://kciter.so/posts/server-monitoring-analysis-guide/)

지연과 에러 같은 사용자 증상에서 출발해 자원 지표와 병목을 함께 읽으며 장애 원인을 좁혀 가는 가이드.

<sub>`모니터링` · `트러블슈팅` · 2026-10-12</sub>

### [켄트 벡(Kent Beck) 형님과 함께하는 Augmented Coding, "증강 코딩" 잘해보기](https://velog.io/@qlgks1/Kent-Beck-Augmented-Coding)

개발자가 주도권을 잡고 테스트와 구조 개선을 병행하는 증강 코딩의 원칙과 실전 워크플로우를 소개하는 글.

<sub>`AI 코딩` · `TDD` · 2026-10-12</sub>
